## Code walkthrough

Data flows in one direction: **API module → `QuizPanel` (state and requests) → display components that only render what they're given.**

**1. API layer: api/survival.ts**
- Three functions matching the three endpoints.
- `SurvivalRequestError` (line 11) extends the existing `QuizRequestError`. That way the start errors (`DOCUMENT_NOT_READY` and so on) reuse the regular quiz's messages, and it also carries the `session` the server sends back with a `409`.
- `readJson` (line 28) reads that session only if it has the expected shape. An HTML error page leaves `code` empty and `session` null.

**2. Coordinator: QuizPanel.tsx**
- **Resume** (the effect at line 110): a saved game is checked before a saved regular quiz. It fetches the session from the server, and a `404` clears the saved id without showing an error. The saved value is `{sessionId, documentIds}` (`readGame`, line 36), never lives or score.
- **`answer`** (line 217) has three guards: it returns early if the `answering` ref (line 102) shows an answer in flight, it passes `busy` down to disable the buttons, and it never retries on its own. On success it stores the server's new session plus the question just answered, so the feedback can still show it after the server has moved on.
- **`409` recovery** (line 230): it switches to `cause.session`. If that session has ended, the render switches to the summary.
- **Which screen shows** (line 263):
  - Restoring: loading message.
  - Running game, or feedback still on screen: game.
  - Ended game: summary.
  - Otherwise the existing regular quiz screens. Feedback after the last answer comes before the summary, so the student sees what they got wrong.

**3. Display: SurvivalGame.tsx**
- The question shown is `feedback?.question ?? session.current_question` (line 21).
- Progress is computed from `current_position` and `status` (line 35). It accounts for the contract's rule that `current_position` stays on the last answered question once the game ends.
- The lost heart is the one at index `session.lives` (line 46), so it comes from server data, not a count kept in the client.
- Focus moves to **Next question** when feedback appears, then back to the question heading (lines 30–31).
- The `role="status"` region (line 77) stays mounted so screen readers announce each result.

**4. Styles: survival.css**
- Selectors start with `.survival` so they outrank the general `.course-workspace button` rules.
- A `@container` query (line 51) switches the options to two columns based on the game's own width, so it still works when the AI Assistant panel narrows the column.
- A just-lost heart's resting style is empty (line 39), and the animation only plays from full to empty. That's why reduced motion still shows the right number of hearts.
