### STUDENT

### AI
Without the lock, **both transactions could read the job as nonterminal, pass the checks, and start applying their callbacks** before either one commits.

### STUDENT

### AI
Because **arrival order doesn’t reliably tell us which result is correct**. A callback that arrives later might be a delayed, stale, or conflicting worker result—not a newer truth. If Django accepted every terminal callback, it could silently replace already-committed chunks and change a successful job to failed, or vice versa.

The tradeoff is that this code doesn’t let a later attempt replace a terminal result, even if that later result might be better. Supporting recovery after a terminal failure would need an explicit retry/reopen policy rather than “accept whichever callback arrived last.”

### STUDENT
so if a later attempt actually fixed the problem, how would we support that without breaking the terminal state rule?

### AI
Treat each **execution** as terminal, rather than reopening it when a retry succeeds:

1. Keep the failed job terminal and preserve its callback receipt.
2. Create a **new job** for the retry, then dispatch work for that job. Its callback can update the document, while callbacks from the older job are rejected as stale—the callback code already checks for a newer job for the same document ([`result_callbacks.py`](C:/Users/crisu/Desktop/CS3398/studyforge/backend/apps/documents/result_callbacks.py:63)).
3. Let the new job reach its own terminal state. That gives the retry a clean callback history without letting a late callback rewrite the old job’s outcome.

If the system must reuse the same job ID, it needs an explicit, atomic “reopen” operation plus a **monotonically increasing attempt or generation token**. Callbacks from earlier generations must be rejected, even after reopening. Simply clearing the terminal status and fingerprint would risk allowing a delayed callback from the old attempt to affect the retried job.

In short: **terminal means final for that job execution; recovery starts a new execution.**
