## Job/document ownership and route assessment

The application owns the authoritative `Document` and `Job` records. The standalone service stores only numeric IDs and the source digest in [`Execution`](</Users/sanishshrestha/Documents/studyforge/services/document-processing/executions/models.py:7>).

The current route correctly enforces:

1. A valid service credential.
2. Existence of the requested Job.
3. Resolution of the Document through that Job.
4. Correlation headers containing the resolved document ID and stored digest.
5. Worker-side verification of those headers and the downloaded bytes.

A document-ID route would weaken this design if it allowed:

`GET /internal/v1/documents/{document_id}/`

because the request would no longer prove which logical Job is being processed. It would increase replay and cross-job confusion risk, duplicate authorization logic, and make stale-job handling harder. It would only be safe if it still required and independently validated a job correlation, which makes it redundant.
