### STUDENT

Explain the difference between a Docker service name and a Celery worker hostname. Show how unique names help me identify which worker processed each document in logs.

### AI

A **Docker Compose service name** identifies a container role in the Compose configuration and on the Compose network. Here, `processing-worker-1` and `processing-worker-2` are separate services: you can start, stop, inspect, and view logs for each independently. Other containers can also use those names for network access.

A **Celery worker hostname** identifies a worker process to Celery. The `--hostname` setting gives each worker a distinct name, such as `processing-worker-1@<container-hostname>`. Celery uses that identity in worker logs and operational features such as events and remote control. It does not identify a document or task.

Together, these names help connect **which worker** handled a task to **which document** it handled. For example:

```text
[INFO/MainProcess] Task apps.processing.tasks.process_document_task[...] received
[INFO/MainProcess] processing-worker-2@...: processing document 481
```

The second line would need the task or application code to log the document ID; the worker hostname alone cannot provide it. If a task succeeds without logging the document ID, the worker name may tell you which worker reported success, but not reliably which document it processed. For dependable tracing, include the document ID (and ideally the Celery task ID) in task-level logs. Unique Celery hostnames let you then distinguish the worker entries, while unique Compose service names let you inspect each container’s logs separately.
