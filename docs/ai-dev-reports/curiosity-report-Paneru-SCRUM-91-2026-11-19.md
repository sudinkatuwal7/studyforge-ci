**Why PATCH and not PUT?** PUT means "replace the whole resource". The client must send every writable field each time, and anything left out counts as cleared. PATCH means "change only these fields", so a client can rename a note without resending all of its sections. A note has three writable fields and several read-only ones, so partial updates fit better. Supporting only PATCH also keeps one code path and one set of tests; PUT will return 405. PUT would work too, so this is a choice, not a requirement.

**Two tabs editing the same note:** as planned, the last save wins with no warning. Tab A saves, then tab B, which still shows the old content, saves and overwrites A's changes. The editor sends title, overview and sections together, so B's old content replaces A's. The usual fix is an optimistic concurrency check: the client sends back the `updated_at` it loaded, and the server returns 409 if the note changed since then.
