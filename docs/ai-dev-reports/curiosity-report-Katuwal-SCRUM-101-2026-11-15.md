### STUDENT
why did we keep the document chunks in django's database instead of storing them in processing service database

### AI
Because chunks are **application data**, not just temporary processing output. Pandu’s retrieval, citations, and Notes read chunks alongside Django’s `Document` and user-ownership records. Keeping them in Django’s database lets those features query them under the same authorization rules and transactionally set a document to `READY` only after its chunks are saved ([architecture contract](C:/Users/crisu/Desktop/CS3398/studyforge/docs/architecture/document-processing-contract.md:90)).

The processing service’s database is for its own execution records. The worker computes chunks and embeddings, then sends them to Django; it doesn’t access or write Django’s application tables directly. Storing chunks there would require another API/data-sync layer—or shared database access—and would split ownership of the data. The tradeoff is that Django handles chunk persistence and retrieval load.
